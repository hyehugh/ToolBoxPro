# Indie Hackers — Build Journey

This is a "build in public" post for indiehackers.com.

## Title

I built 100 tools, $0 hosting, and learned why "privacy-first" actually sells

## Story

**Who I am:** A solo developer who wanted to prove you don't need a backend to build a useful product.

**The idea:** Most "free online tools" secretly upload your files to a server. I wanted to build 100+ tools that are genuinely private — everything runs in your browser.

**The build (6 weeks):**
- Week 1-2: Built 20 core tools, scrappy MVP
- Week 3-4: Expanded to 100 tools across 8 categories
- Week 5-6: Wrote 30 blog posts, polished UI, fixed edge cases

**Tech stack:** Next.js 15 + Tailwind v4 + TypeScript. All tools use browser APIs. No backend. Hosted on Vercel free tier.

**The best technical decision:** Using pdf-lib for PDF processing and Canvas API for images. These are standard browser APIs, so no license costs, no CDN dependencies, no third-party services.

**The worst technical decision:** Building all 100 tools before validation. I should have launched with 20 and watched what users actually wanted.

**Revenue model:** Google AdSense (not yet approved). Long-term: non-intrusive ads + optional premium features.

**Current status:** Launched at https://trytoolboxpro.com. Awaiting Google index. Starting to promote on Reddit, HN, and Dev.to.

**Lesson for other indie hackers:**
1. "Privacy-first" is a real differentiator — lean into it
2. Blog + tools combo works for SEO (Google loves context)
3. Launch early, even if not everything is perfect
4. $0 hosting is possible — Vercel + static site FTW

**Metrics so far:**
- 100+ tools, 8 categories
- 30 blog posts
- 136 pages indexed
- $0 hosting cost

Ask me anything about building 100 tools without a backend!
